# 图语家微信小程序独立检出与构建说明

- 更新时间：`2026-07-29 11:43:32`
- 执行工具 / 模型：`Codex（GPT-5）`

## 1. 为什么需要两个仓库

微信仓库是独立的 Taro UI 和平台适配项目，但不会复制 CBoard 的通信业务核心。构建配置把 `@cboard-communication-core` 映射到相邻 `cboard` 工作树中的 `src/common/communicationSupport`，默认板生成器也从同一工作树读取板、翻译和原始图符。

因此，“独立检出”表示从空目录按公开步骤取得全部对应源码，不表示只克隆微信仓库就能脱离 CBoard 构建。

## 2. 目录结构

两个仓库必须位于同一个父目录：

```text
picinterpreter-workspace/
├── cboard/
└── picinterpreter-wechat/
```

## 3. 从空目录检出

```powershell
New-Item -ItemType Directory picinterpreter-workspace
Set-Location picinterpreter-workspace

git clone --branch feature/tuyujia-mvp --single-branch https://github.com/lightcoloror/cboard.git cboard
git clone https://github.com/lightcoloror/picinterpreter-wechat.git picinterpreter-wechat

Set-Location picinterpreter-wechat
```

当前可复现基线：

- CBoard：`055e26e59d38f5f0db8136fc00e4234bffdae23c`
- 微信仓库：以 `main` 最新提交为准

需要严格复现实验结果时，可在对应仓库检出上述 CBoard 提交；日常开发应继续使用 `feature/tuyujia-mvp` 的最新兼容版本。

## 4. 安装

已验证环境：

- Windows
- Node.js 22
- Yarn 1.22.22
- 微信开发者工具 Nightly Electron Build 2.02.2607032 或更新版本

```powershell
yarn install --frozen-lockfile
```

仓库不要求全局安装 Taro CLI，所有命令都调用本地依赖。

## 5. 验证源码边界

```powershell
yarn check:boards
yarn test
yarn typecheck
yarn lint
yarn check:boundary
yarn build:weapp
```

各命令职责：

- `check:boards`：确认生成板与相邻 CBoard 源文件的哈希一致。
- `test`：执行纯核心、会话、存储、图符归属和功能回归。
- `typecheck` / `lint`：检查 TypeScript 与代码风格。
- `check:boundary`：阻止 React DOM、Material UI、浏览器 API 或越界 CBoard 模块进入微信包。
- `build:weapp`：生成 `dist`，并在构建后执行微信包体和资源质量门。

## 6. 在微信开发者工具中运行

1. 执行 `yarn dev:weapp`，保留后台 watch 进程。
2. 在微信开发者工具中导入 `picinterpreter-wechat` 仓库根目录，不要只导入 `dist`。
3. `project.config.json` 已把 `miniprogramRoot` 指向 `dist`。
4. 当前 AppID 是公开标识，不等于 AppSecret；AppSecret 和服务端密钥不得写入客户端或提交到 Git。
5. WechatSI 需要当前 AppID 已在公众平台添加插件并获得对应版本权限。

## 7. 本地私有配置

- `project.private.config.json` 已被 `.gitignore` 排除，可保存开发者工具的本机设置。
- API 地址通过本地环境变量 `TARO_APP_API_BASE_URL` 注入，不要把令牌或服务端密钥写入 `.env.*`。
- 登录、AI、云同步和在线图符需要手机可访问的 HTTPS `cboard-api` 以及微信合法域名配置；缺失时本地核心仍应安全降级。

## 8. 常见失败

### 找不到 `@cboard-communication-core`

确认父目录下的仓库文件夹名严格为 `cboard`，且存在：

```text
cboard/src/common/communicationSupport
```

### `check:boards` 报哈希不一致

CBoard 板或翻译发生了变化。先确认是否应升级生成物；需要升级时执行 `yarn generate:boards` 并审查板数量、图符归属和包体变化，不要直接跳过检查。

### WechatSI 不可用

确认使用正式 AppID、公众平台已添加“微信同声传译”插件、插件版本与 `src/app.config.ts` 一致，并重新编译预览。

### 微信包体超限

运行 `yarn build:weapp` 查看逐包质量门。不要关闭检查；优先拆分分包、移除无依赖文件或把非必要大资源迁移到受控 CDN。

## 变动依据

- 意图：让任何获得仓库权限的人都能从空目录复现当前工程，不依赖本机绝对路径或历史缓存。
- 决策：保留双仓复用架构，并把相邻目录、分支、基线提交、依赖安装、质量门和开发者工具导入方式写成明确步骤。
- 理由：复制 CBoard 核心会制造双端漂移；不说明相邻仓库又会导致单仓克隆必然构建失败。
- 证据：`config/index.ts`、`vitest.config.ts`、板生成脚本和边界检查均显式解析相邻 `cboard`；当前完整测试与生产构建已在该结构下通过。
- 生效范围：本地开发、CI 和后续迁移到 `picinterpreter` 账号后的工程检出；仓库 URL 或目标分支变化时必须同步更新本文。
