# 订阅状态只读展示与支付安全边界

- 记录时间：`2026-07-22 21:32:34`
- 执行工具 / 模型：`Codex（GPT-5）`

## 变动 1：复用 CBoard 登录响应中的订阅摘要

- **意图：** 让照护者在小程序中看见与 CBoard Web 相同的订阅事实，而不是在微信端维护第二份状态。
- **决策：** 扩展现有 `CboardAccountPort` 会话契约，只接收 subscriber ID、状态、到期时间以及套餐标题、周期和展示价格。
- **理由：** 订阅状态必须由 cboard-api 的供应商校验结果决定；复用登录响应比增加微信专用接口或本地布尔值更可靠。
- **证据：** `cboardAccountPort` 测试覆盖登录响应解析、状态规范化和购买令牌/收据/签名丢弃。
- **生效范围：** 微信账号 port 和认证会话；不改变患者沟通主链或 CBoard API 路由。

## 变动 2：只持久化脱敏后的只读状态

- **意图：** 刷新小程序后仍可显示最近一次服务端确认状态，同时避免把支付秘密写入微信 storage。
- **决策：** `cboardSession` 只保存规范化订阅摘要，主动排除 settings、provider 原始交易、购买令牌、收据、签名和付款人数据。
- **理由：** 微信 storage 不是支付凭据仓库；最小摘要足够支持 UI，真实有效性仍由下次登录或服务端刷新确认。
- **证据：** session 测试证明摘要可以保存和恢复，未授权字段不会进入序列化结果，旧 token 会话继续兼容。
- **生效范围：** `cboard_account_session`；不会修改沟通历史、私人图片、录音或常用语存储。

## 变动 3：在照护管理页展示但不扣费

- **意图：** 让用户知道当前订阅、方案和到期时间，并明确避免把只读展示误解为微信自动收费。
- **决策：** 在现有“CBoard 账号与云同步”面板中显示中文状态、当前方案和到期时间，并固定提示“微信端当前仅显示服务端确认的订阅状态，不会在此处自动扣费”。
- **理由：** 订阅管理属于照护者区域，不应进入患者快速表达入口；没有完整微信支付链时也不应展示虚假购买按钮。
- **证据：** 小程序全量 `65 files / 289 tests`、TypeScript、ESLint、边界检查和 production build 通过。
- **生效范围：** management 分包账号页；患者表达、接收、分词、匹配、语音和离线能力不变。

## 变动 4：维持小程序性能与真实支付边界

- **意图：** 增加订阅可见性时继续遵守微信包体、按需加载和无用依赖要求。
- **决策：** 不加入 Web PayPal SDK、React DOM、Material UI 或新的支付依赖；继续使用纯 TypeScript 契约和现有 Taro 组件。
- **理由：** 支付 SDK 和供应商密钥不应进入患者客户端；真正微信支付应复用官方服务端下单与 `wx.requestPayment` 流程，待商户前提齐全后单独实现。
- **证据：** production build 通过；main `1,249,564 B`、management `503,194 B`，所有分包低于 1.5 MiB 建议线。
- **生效范围：** 当前小程序源码和构建产物。插件实际下载体积仍需上传前使用微信开发者工具性能扫描验证；本轮未预览、上传或发布，也未打开、激活、聚焦、抬升或置顶任何窗口。
