## 一、代码实际使用的数据与权限

| 功能 | 微信接口或实现 | 数据去向 | 公众平台需要核对 |
| --- | --- | --- | --- |
| 普通话语音输入 | WechatSI `getRecordRecognitionManager` | 微信插件提供方处理录音并返回文字 | 麦克风、录音/语音识别、第三方插件 |
| 方言语音输入 | `getRecorderManager`、`uploadFile` | 用户主动选择后上传至正式 `cboard-api` | 麦克风、录音、网络上传、服务提供方 |
| 图卡录音 | `getRecorderManager`、`saveFile` | 默认只保存在当前设备 | 麦克风、本地文件保存 |
| 个人图片和视频 | `chooseMedia`、`saveFile` | 默认只保存在当前设备；主动云备份时才上传 | 选中的照片或视频、本地文件、可选云同步 |
| 图片识字 | `chooseMedia`、`uploadFile` | 用户确认后上传至正式 `cboard-api` | 选中的照片、图片识别、服务提供方 |
| AAC/备份导入 | `chooseMessageFile`、文件系统 | 小文件本机解析；需要服务转换时上传至正式 API | 选中的文件、文件上传 |
| 在线缺词补图 | `request`、`downloadFile`、`saveFile` | 单个缺词发送至 CBoard API 或 ARASAAC；确认后保存图片 | 网络请求、第三方图库、下载文件 |
| 账号与云同步 | CBoard 邮箱/手机账号 API | 账号资料、设置、常用语、已确认记录发送至正式 API | 账号信息、手机号、云同步、删除与注销 |
| AI/去背景/图卡建议 | `request` 或 `uploadFile` | 用户主动触发后由正式 API 转发到所配置服务商 | AI 服务商、处理目的、保留时间、跨境情况 |

当前代码没有使用微信定位、通讯录、蓝牙、微信头像昵称、微信手机号授权或 `wx.login`。账号体系是 CBoard API 的邮箱/手机账号；后台声明不应添加代码没有使用的权限。

## 二、已补齐的代码保护

- 全局监听 `onNeedPrivacyAuthorization`，只在用户主动触发隐私接口时显示授权说明。
- 用户可查看微信后台配置的《用户隐私保护指引》，也可拒绝；拒绝不阻止无需权限的本地沟通。
- `app.json` 声明 `scope.record` 的真实用途，不以模糊文案索取麦克风。
- 设置页显示“隐私、开源与第三方素材”，公开说明默认本机保存、哪些功能会联网。
- 未配置公众可访问源码地址时，设置页明确标记“不可作为正式公开发布版本”。

## 三、公众平台填写清单

登录 https://mp.weixin.qq.com 后，在“设置 / 服务内容声明 / 用户隐私保护指引”按后台当前选项逐项填写：

1. 麦克风和录音：用于用户主动语音输入、方言识别和个人图卡录音。
2. 选中的照片或视频：用于创建个人熟悉图卡、图片识字和可选去背景；默认保存在本机。
3. 选中的文件：用于导入 AAC 图板和本机备份。
4. 账号信息：邮箱、手机号码仅在用户主动注册、登录或找回密码时发送到 CBoard API。
5. 沟通数据：只有用户主动登录并同步时，常用语、设置和已确认沟通记录才进入云端。
6. 第三方处理者：WechatSI、正式 CBoard API 运营主体、实际启用的 AI/语音服务商。
7. 在线图库：ARASAAC 直连只发送单个缺词；OpenSymbols 只通过 CBoard API 代理。
8. 保存期限与删除：写明本机数据如何清理、云端账号如何注销、备份如何删除。
9. 联系方式：填写真实可响应隐私请求的邮箱或电话，不能使用开发占位信息。

后台保存后，必须用从未授权过的新微信账号测试“同意、拒绝、重新授权、后台新增数据类型后再次授权”四条路径。

## 四、正式 HTTPS 后端与合法域名

正式版本必须配置一个手机可访问的 HTTPS CBoard API，例如 `https://api.<你的域名>`。不能使用 `localhost`、局域网 IP、自签名证书或只在开发电脑可访问的地址。

公众平台“开发管理 / 开发设置 / 服务器域名”至少核对：

| 域名 | 微信域名类型 | 用途 |
| --- | --- | --- |
| 正式 CBoard API | `request` | 登录、同步、AI、OCR、服务健康、公开图库 |
| 正式 CBoard API | `uploadFile` | OCR、方言录音、AAC 转换、图片增强 |
| 正式 CBoard API | `downloadFile` | 私有图库备份、公开图板、OpenSymbols 代理图片 |
| `https://api.arasaac.org` | `request` | CBoard API 不可用时的单词补图备用搜索 |
| `https://static.arasaac.org` | `downloadFile` | 人工确认后下载 ARASAAC 图片 |

OpenSymbols 不应由小程序直接连接任意图片域名；继续通过 CBoard API 的同源签名代理，避免任意下载域名和客户端密钥。

## 五、图符与开源许可证门

当前随包 871 张图卡按来源分为：

- Mulberry：792 张，`CC BY-SA 4.0`。
- ARASAAC：62 张，`CC BY-NC-SA 4.0`，作者 Sergio Palao。
- CBoard 自有：17 张，上游没有提供逐图独立许可。

正式公开前必须完成：

1. 在图卡展示或统一“关于/来源”入口保留作者、图库、许可证和来源链接。
2. 若小程序或主体用途构成商业使用，取得 ARASAAC 许可，或替换全部 ARASAAC 图符。
3. 向 CBoard 维护者确认 17 张自有图符的再分发许可；无法确认时替换。
4. 对新增在线候选继续保存并展示每张图的独立 attribution，不把 OpenSymbols 当作统一许可证。

## 六、GPLv3 源码门

微信代码包会编译 CBoard GPLv3 通信核心。正式向公众分发前，最简单、可核验的方案是：

1. 在 `picinterpreter` 账号建立公开的 `picinterpreter-wechat` 仓库。
2. 同时公开或链接精确对应版本的 `cboard` fork。
3. 保留完整构建脚本、`yarn.lock`、GPLv3 文本、第三方声明和对应提交号。
4. 在生产环境设置 `TARO_APP_SOURCE_CODE_URL`，让设置页可复制公众源码地址。
5. 用未登录浏览器确认任何人都能获取与发布代码包对应的源码。

当前 `lightcoloror/picinterpreter-wechat` 是私有仓库，因此只能作为备份和开发源，不能勾选“源码公众可访问”。

## 七、上线门禁

先复制本地证明文件：

```powershell
Copy-Item release-readiness.example.json .release-readiness.local.json
```

逐项填写真实证据后运行：

```powershell
yarn check:release-readiness
```

该文件已被 Git 忽略，不用于存放密钥，只记录账号、备案、隐私、域名、许可、真机和性能扫描是否已人工确认。任何一项未完成，命令都会列出阻断原因并返回失败。

## 变动依据

- 意图：把“隐私和许可证以后再看”改成上传前无法忽略的显式门禁。
- 决策：隐私授权在用户触发时按需出现；上线证明保存在不入库的本地 JSON；代码构建与正式发布检查分离。
- 理由：后台声明不能替代运行时代码，普通构建通过也不能证明备案、域名、源码公开或素材许可已经完成。
- 证据：实际微信 API 扫描、Taro 隐私接口类型、CBoard/ARASAAC/Mulberry 来源清单、生成图板归属测试及微信官方隐私开发文档。
- 生效范围：图语家微信小程序正式发布准备；不代表微信、通信管理局或素材权利人已经批准。
