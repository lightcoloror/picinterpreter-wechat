## 变动 1：分层验收门

- **意图：** 把“纯核心正确”“微信包可编译”“开发者工具可操作”和“真机可用”分开，避免用低层证据替代高层验收。
- **决策：** 保留四层门：Vitest/边界扫描、Taro production build、开发者工具自动化、真机手工验收。任一层未执行时明确标为未验证。
- **理由：** 单测不能证明微信 WXML 事件、独立结果页、平台 storage 或触控；开发者工具也不能证明真机横竖屏、系统断网和语音能力。
- **证据：** `scripts/weapp-smoke.mjs`、`scripts/wechat-cli-port-shim.cjs`、`yarn test:e2e:weapp`，以及本清单下方的结果表。
- **生效范围：** `cboard-wechat-poc` 的本地验收与后续 issue #33/#65/#67/#68；不改变小程序业务代码。

## 变动 2：开发者工具自动化前置条件显式化

- **意图：** 在 Windows TCP 排除区间与开发者工具安全设置不同的机器上，仍能得到可解释、可复现的启动结果。
- **决策：** Windows 使用开发者工具自带的 `node.exe` 和 CLI，通过进程内加载钩子只替换 CLI 硬编码的 `3799` 桥接端口；普通命令不会自动开启 IDE 服务端口，只有带 `--enable-ide-service` 的一次性命令会向官方提示输入 `y`。
- **理由：** 本机 `3799` 位于 Windows 排除区间 `3720-3819`，当前 CLI 对 `EACCES` 不会自动换端口；同时 IDE 服务端口是持久化安全设置，不能由普通测试静默打开。
- **证据：** CLI 原始错误为 `listen EACCES: permission denied 127.0.0.1:3799`；绕过该端口后官方 CLI 明确提示 `IDE service port disabled` 并要求确认开启。
- **生效范围：** 仅本地开发者工具自动化进程；不修改微信开发者工具安装文件、Windows 端口排除策略、`dist` 生产包或真机设置。

## 变动 3：登录态与 AppID 前置条件实证化

- **意图：** 区分“工具未安装”“服务端口关闭”“账号未登录”和“小程序页面代码失败”，避免把环境阻塞误判成业务回归。
- **决策：** 用官方 CLI `islogin` 验证登录态；服务端口启用后仍先检查登录，未登录时只生成本地二维码等待管理员或开发者扫码，不调用 preview、upload 或发布接口。
- **理由：** 自动化连接成功并不代表 app launch 已 ready；账号 token 缺失时继续重试页面协议只会制造误导性超时和待处理请求。
- **证据：** 首轮官方 CLI 返回 `{"login":false}`，日志记录 `access_token missing`；用户在开发者工具登录后，CLI 返回 `{"login":true}`，该阻塞已经排除。
- **生效范围：** 本机微信开发者工具登录前置检查和 UI E2E 诊断；不把真实 AppID 或 AppSecret 写入仓库，不改变小程序 runtime、CBoard core 或真机账号。

## 变动 4：本机 AppID 与仓库配置隔离

- **意图：** 在真实小程序身份下完成模拟器验收，同时保持未来 PR 不携带个人或项目私有联调配置。
- **决策：** `project.private.config.json` 只在本机保存真实 AppID并加入 `.gitignore`；公共 `project.config.json` 继续保留游客占位值，任何 AppSecret 均不得进入小程序目录。
- **理由：** 当前开发者工具登录成功后仍报告 `appid missing`，说明新版环境不再接受本项目的游客占位路径；私有配置具有更高优先级且专用于开发者本地差异。
- **证据：** CLI `islogin` 返回 `true`；写入私有配置并用官方 CLI 关闭、重新打开项目后，`appid missing` 消失，首页 route、用户代码、webview 和截图正常加载。
- **生效范围：** 当前工作站的小程序导入与 UI E2E；不进入 Git 提交、生产包、云同步、preview、upload 或发布流程。

## 变动 5：官方 Skill 作为首选控制面

- **意图：** 使用微信官方维护的 Agent 控制入口，减少旧 SDK、私有协议和 Windows 端口兼容层带来的脆弱性。

- **理由：** 官方 Skill 随开发者工具同步并覆盖编译、模拟器、日志、导航、页面、元素和截图；PowerShell 7 可避免 MSYS 对 `/pages/...` 的路径转换以及中文输出编码问题。
- **证据：** `weapp-dev-mcp` README 已建议迁移官方 Skill并给出最低 Nightly 版本；Windows 实践记录验证 `wechatide` 可自动发现端口。本机 `miniprogram-automator 0.12.1` 对原生页面 `Page.*` 成功、对 Taro 页面悬挂，说明继续包装旧 SDK 不能替代新控制面验证。
- **生效范围：** 后续本地 Codex 自动化；本轮不升级开发者工具，不自动 preview/upload，不写云资源，不发布小程序。

## 变动 7：修复“想喝水”丢失对象图卡

- **意图：** 保证接收者输入“想喝水”时，患者看到的序列包含“我想要 / 喝 / 水”，而不是只剩“我想要 / 喝”。

- **生效范围：** Web 与微信共享的文字分词、图卡匹配和接收管线；不更改 CBoard 默认板、API、AI 或云同步。

## 变动 12：插件授权阻断与缓存恢复流程

## 变动 13：照护者 ASR 入口与文字兜底验收

- **生效范围：** 微信接收页、WechatSI 语音识别 adapter、录音权限描述和自动化稳定 ID；不新增云端 ASR、不改共享 matcher，也不把模拟器验收写成真机录音通过。
