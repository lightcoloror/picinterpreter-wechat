### 变动 1：把微信官方性能建议分成自动门和人工门

- **意图：** 防止只凭 Taro 编译成功就认为小程序满足包体、资源、插件和组件质量要求。
- **决策：** production postbuild 自动检查单包 2 MiB 硬限制、1.5 MiB 分包建议线、200 KiB 媒体、脚本/WXML/WXSS 压缩、未使用文件过滤、按需注入、插件生产调用、页面级未使用组件、共享 WXSS 引用和默认图卡去重。插件实际下载体积与主包依赖归属继续由微信开发者工具官方性能扫描确认，不伪造本地静态结论。
- **理由：** 插件二进制不在本地 `dist`，主包依赖归属还依赖微信上传分析器；本地脚本无法可靠计算的项目应显式留给官方工具。其余确定性项目应在每次生产构建自动失败，而不是等上传后人工发现。
- **证据：** 微信官方《小程序性能优化指南》列出 12 项扫描要求；本项目 `scripts/check-weapp-output.mjs` 和 `project.config.json` 已覆盖其中可由产物证明的项目。
- **生效范围：** 小程序 production 构建与发布前验收；不改变患者沟通、图板、语音、网络、账号或业务数据。

### 变动 2：插件和组件检查不再接受跨范围假证据

- **意图：** 修复测试源码或其他页面的标签意外让未使用插件、未使用组件检查通过。
- **决策：** 插件必须在 production JavaScript 中出现与配置名称一致的静态 `requirePlugin` 调用；每个 `usingComponents` 默认只检查同名页面或组件 WXML 及其 `import/include` 依赖闭包，只有全局 app 配置才能使用完整 WXML 清单。
- **理由：** 测试里调用插件不能证明发布包会调用；A 页面使用组件也不能证明 B 页面的同名声明有用。按声明作用域检查才能对应微信官方“无使用插件/组件”要求。
- **证据：** Node 内建测试覆盖正确插件、错误插件、动态名称拒绝、页面隔离、全局组件和 WXML 依赖提取；测试无需新增第三方依赖，也不派生测试子进程。
- **生效范围：** 小程序质量脚本和 npm 测试链；不删除当前 WechatSI 或 Taro `comp` 组件。

### 变动 4：统一图片失败占位支持人工重试

- **意图：** 在图卡文件有效但微信运行时发生瞬时加载失败时，让患者或照护者能在原位置恢复图片，而不是只能停留在占位文字或重开页面。

### 变动 5：图库归档复用 fflate 并按声明大小有界解压

- **意图：** 降低微信“本机数据工具”低频页面的脚本和分包体积，同时让万级图卡归档恢复不再依赖 JSZip 私有字段或一次性展开整个 ZIP。
- **决策：** 精确复用 [fflate 0.8.3](https://github.com/101arrowz/fflate) 的 MIT ZIP/UTF-8 实现和 `base64-js 1.5.1`，只替换图语家图库备份、恢复与 OBF/OBZ 读取链。写出时 JSON 使用 DEFLATE，已经压缩的图片和录音使用 ZIP STORE；读取时先扫描中央目录，拒绝重复条目、路径穿越、条目数和声明大小越界，再按最多 `250` 项、`16 MiB` 一批恢复媒体。JSZip 继续作为 Gridset/AACTools 和跨实现测试的生产依赖，不误删。没有采用动态 `import()`，因为 [Taro 官方文档](https://docs.taro.zone/en/docs/dynamic-import) 明确说明微信小程序默认会把它转换为同步 `require`，社区动态加载方案还存在审核驳回风险。
- **理由：** fflate 是成熟、纯 JavaScript、支持 ZIP 读写和按条目原始大小过滤的开源库，完整能力体积明显小于 JSZip；媒体本身已经压缩，重复 DEFLATE 只增加 CPU。先索引后分批解压既减少内存峰值，也比读取 JSZip `_data.uncompressedSize` 私有结构更稳定。Gridset 仍需要既有 JSZip 兼容层，强行一次替换 CBoard 全站导入器会扩大风险且不属于当前小程序性能切片。
- **证据：** 新增 fflate 写出、JSZip 跨实现读取、UTF-8、二进制、路径、条目数和压缩炸弹声明大小测试；图库服务继续覆盖 ZIP 导出/恢复、云端复核、篡改、OBF/OBZ/GRD/Gridset/Snap/TouchChat、图片/录音和回滚。微信全量 `73 files / 325 tests`、`7/7` 质量门、TypeScript、ESLint、`204 app / 30 CBoard core` 边界及 yarn 完整性通过。最终 production build 成功：main `1,249,620 B` 不变，backup 从变动 201 的 `913,444 B` 降至 `832,869 B`，减少 `80,575 B`，距 `1.5 MiB` 建议线剩余 `739,995 B`；library 页面由 `444,366 B` 降至约 `355 KiB`。
- **生效范围：** 微信小程序 backup 分包的图语家图库 ZIP、完整本机数据 ZIP、云端私人图库复核恢复和 OBF/OBZ 媒体读取；不改变归档 manifest、冲突策略、恢复事务、患者表达、CBoard Web、cboard-api、Gridset parser、Snap/TouchChat 服务端转换、分词、匹配或语音。`355 KiB` 页面仍触发 Webpack 通用 `244 KiB` 警告，但分包远低于微信 `1.5 MiB` 建议线；进一步拆分需要把 AAC 导入服务与备份服务分成独立页面/模块，不能通过不真实的动态 import 完成。插件下载体积和官方性能扫描仍待开发者工具人工门。本轮未打开、激活、聚焦、抬升或置顶开发者工具，未预览、上传、发布、部署、提交或推送。
