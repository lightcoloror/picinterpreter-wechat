# 微信小程序上线前可完成开发收口

> 当前状态：代码侧准备已完成；域名、云服务器、备案、供应商购买和真实公网验收保持等待。

## 正式发布运行模式

- 意图：保证没有后端和云服务时，小程序仍能安全提供离线双向沟通，而不是显示可点击但必然失败的联网功能。
- 决策：生产构建默认关闭云同步、AI、OCR、在线补图和方言云识别；每项能力必须有显式 `true` 开关。依赖 API 的能力还必须配置公网 HTTPS 地址。
- 理由：正式包必须失败关闭，不能因忘记环境变量而向测试地址、局域网地址或第三方服务发送数据。
- 证据：运行时能力单元测试覆盖生产默认关闭、显式开启、拒绝 HTTP/localhost 以及预览环境兼容；TypeScript 检查和生产构建纳入最终验证。
- 生效范围：微信小程序网络适配器、接收端图片识字入口、账号与云同步、AI、服务端语音、方言识别和在线图符搜索。

## 可选服务与最小后端

- 意图：在尚未购买短信、Azure、AI 等服务时，仍能先完成基础 API 的部署准备。
- 决策：MongoDB、HTTPS、会话密钥、JWT 密钥和限流是基础必需项；Azure 私有图库与腾讯短信只在启用后要求完整配置。
- 理由：购买顺序不应阻断工程准备，但启用半套供应商配置会产生安全与数据风险，因此继续失败关闭。
- 证据：API 生产配置检查器和 7 条单元测试已覆盖最小配置、完整配置、半配置拒绝、限流和可选方言识别。
- 生效范围：`cboard-api` 生产环境模板、Docker Compose 和上线前校验。

## 部署、健康检查与数据恢复

- 意图：把服务器购买后的部署动作压缩为可重复命令，并在首次用户试用前具备恢复能力。
- 决策：部署前必须校验配置，启动后必须通过公网 HTTPS `/health`；MongoDB 备份默认权限受限并保留 14 天；恢复必须显式确认。
- 理由：容器运行不代表微信真机可访问，数据库备份也不能以可误触恢复为代价。
- 证据：生产模板检查已通过，检查器会静态验证部署、健康检查、备份和恢复脚本的安全约束。
- 生效范围：未来腾讯云轻量应用服务器或兼容 Docker Compose 的 Linux 主机；尚未宣称真实公网通过。

## 图符发布许可门

- 意图：让公司主体发布前准确知道哪些随包素材仍待授权或替换。
- 决策：提交机器可读的 871 图卡逐项清单；792 个 Mulberry 图卡按现有许可与署名规则标记可用，62 个 ARASAAC 和 17 个 CBoard 图卡保持待处理并阻断正式发布检查。
- 理由：ARASAAC 许可含非商业限制，CBoard 自有分类图缺少逐图明确许可证据，不能把开发测试可用等同于公司主体可发布。
- 证据：许可清单生成器从实际 46 个默认板计算得到 `792 / 62 / 17`，普通一致性检查通过，正式发布检查按预期失败并列出两个待处理来源。
- 生效范围：微信小程序随包的 46 个默认板、871 个图卡和 798 张去重图片。

## 等待外部条件

2. 公司实名认证、域名 ICP 备案和小程序备案。
3. DNS 解析、HTTPS 证书签发和微信合法域名配置。
4. 决定是否购买短信、AI、OCR、在线补图或方言识别服务。
5. 取得 ARASAAC 商业适用许可并确认 CBoard 图符许可，或替换 79 个待处理图卡。
6. 完成真机公网、弱网、断网恢复、备份恢复演练和首批用户验收。
