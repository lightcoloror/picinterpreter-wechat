# 大型 AAC 词库导入与本机双槽存储决策

## 变动 1：大型词库不再依赖单个微信 storage 键

- **意图：** 让从 TouchChat、Snap、Open Board 等来源导入的万级图卡在微信小程序重启后仍能完整恢复，同时避免为持久化重新开发数据库。
- **决策：** 复用微信用户目录同步文件 API，在 `USER_DATA_PATH/picture-library` 中轮换写入 `boards-a.json` 与 `boards-b.json`。每次先写非活动槽、回读确认内容一致后再切换活动标记，上一槽继续作为损坏回退；旧 `Taro.getStorageSync` 数据读取成功后自动迁移到文件。文件 API 不可用或写入失败时，继续回退到原 storage 行为。
- **理由：** 完整 TouchChat 词库可达到 `348` 板面和 `11,953` 按钮，单个同步 storage 键不是可靠的长期载体。A/B 双槽使用微信原生能力、没有新增依赖，且比覆盖同一文件更能抵御中途写入失败；保留 storage 回退则不会破坏旧用户和不具备文件能力的测试/兼容环境。
- **证据：** 自动化覆盖优先读取活动槽、活动槽损坏时读取上一槽、写入非活动槽后切换、旧 storage 自动迁移、文件写入失败回退和清空双槽；微信全量 `72 files / 321 tests`、`7/7` 输出质量门、TypeScript、ESLint 与 `202 app / 30 CBoard core` 边界检查通过。production build 成功，main `1,249,620 B`、backup `913,444 B`，均低于 `1.5 MiB` 建议线。
- **生效范围：** 微信小程序本机图片库的加载、保存、重置和旧数据迁移；不改变患者表达 UI、云同步、账号 settings、文件导入格式、图片匹配、语音或 AI。真实手机上的万级文件写入、异常断电恢复和系统清理用户目录仍需验收；backup 页 `434 KiB` JavaScript 构建警告另列为性能拆分债务。
- **记录：** Codex（GPT-5），2026-07-26 08:45:41。

## 变动 2：跨端总量上限与真实样本对齐但保持有界

- **意图：** 覆盖真实大型 AAC 词库，同时继续阻止异常文件无上限占用内存和包体。
- **决策：** 微信可接收最多 `500` 个 Open Board 文档，并将图片库、归档和结构化图卡容量统一到最多 `20000` 项；服务端继续承担供应商格式解析和字节级防护，小程序只消费版本化 Open Board 响应。
- **理由：** 公开 AACTools 样本已超过旧的 `100/5000` 验证阈值，但没有证据支持取消所有边界。统一客户端容量可避免服务端转换成功后在小程序保存或备份阶段被截断。
- **证据：** 真实 `WordPower42 Basic SS_UK.ce` 转换得到 `348` 个板面、`11,953` 个按钮；共享核心自动化覆盖 `120` 板面、`6000` 按钮以及 `12000` 图卡备份/结构化图库，超出 `500/20000` 时仍明确拒绝。CBoard 全量 `200 suites / 1352 tests / 72 snapshots` 及隔离 production build 通过。
- **生效范围：** CBoard 共享 Open Board 核心、微信 backup 分包的导入与本机图库；不放宽 `20 MiB` 输入、`32 MiB` 输出、单图 `5 MiB`、图片总计 `20 MiB`、`100×100` 网格或服务端并发 `2` 的既有安全边界。
