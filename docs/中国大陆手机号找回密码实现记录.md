# 中国大陆手机号找回密码实现记录

- 记录时间：`2026-07-22 20:38:50`
- 执行工具 / 模型：`Codex（GPT-5）`

## 变动 1：在照护管理账号页增加找回入口

- **意图：** 让忘记 CBoard 密码的图语家用户无需离开小程序即可完成手机号验证并设置新密码。
- **决策：** 在现有邮箱登录、短信登录和注册旁增加“手机找回密码”模式；复用同一手机号输入、发送倒计时和验证码确认组件，purpose 固定为 `password-reset`。
- **理由：** 账号恢复属于照护管理而非患者表达主链，放在 management 分包可以保持患者入口简洁并避免增加主包启动负担。
- **证据：** Taro production build 成功，产物中 management 分包 `501,244 B`，主包保持 `1,249,564 B`。
- **生效范围：** 微信 management 账号与同步面板；患者表达、接收、朗读、分词、图文匹配和离线历史不受影响。

## 变动 2：复用平台无关账号 port

- **意图：** 不在 Taro 组件里复制 HTTP、错误映射或 CBoard session 逻辑。
- **决策：** 扩展 `CboardAccountPort` 的公开配置和 purpose 联合类型，并增加 `resetPasswordWithPhone`；组件只传手机号、一次性验证令牌和新密码，服务端成功后不保存新 session。
- **理由：** 微信是 CBoard 的新客户端，不是新的账号后端。纯 TypeScript port 可单测、可替换 adapter，也让未来其他平台继续复用同一协议。
- **证据：** `cboardAccountPort` 测试覆盖能力字段、purpose 透传、重置端点、弱密码和未验证状态；小程序全量 `65 files / 289 tests` 通过。
- **生效范围：** 微信账号 port 和 management 编排。短信密钥、原始验证码、密码哈希和账号存在性判断均不进入微信 storage。

## 变动 3：保护人工确认和敏感表单状态

- **意图：** 防止错误手机号、旧 challenge 或切换页面后残留的新密码被误用于其他账号流程。
- **决策：** 修改手机号立即清除 challenge/令牌；重置前要求两次密码一致且长度 6 到 128 位；切换到邮箱登录、短信登录或注册时清空两个密码字段；成功后回到登录，失败后也清除已消费令牌和密码，要求重新验证。
- **理由：** 验证令牌是一次性的，新密码也不应跨表单模式复用。人工二次输入可减少移动端输入错误，重新登录避免把找回流程误当作认证会话。
- **证据：** TypeScript 和完整 ESLint 通过；API controller 回归证明 password-reset token 一次消费、弱密码拒绝和无自动登录。
- **生效范围：** 当前小程序进程内表单状态。不会把密码、验证码或验证令牌持久化到微信 storage。

## 变动 4：维持小程序性能和发布边界

- **意图：** 增加账号恢复时继续遵守微信代码包、按需加载和无用依赖约束。
- **决策：** 不引入认证 SDK、Web UI、React DOM 或 Material UI；继续复用 29 个纯 CBoard core 文件和既有 Taro 组件，账号页留在分包。`lazyCodeLoading: requiredComponents` 和现有构建质量门保持不变。
- **理由：** 找回密码只需要少量平台胶水，引入第二套框架会放大包体和维护面，也与 CBoard 账号体系冲突。
- **证据：** 边界检查 `186 app / 29 CBoard core`；生产构建输出为主包 `1,249,564 B`、caregiver `561,956 B`、emergency `93,229 B`、management `501,244 B`、backup `591,378 B`、OCR `63,919 B`，均低于 1.5 MiB 建议线。
- **生效范围：** 微信源码、management 分包和 production 构建门。插件下载体积不能从 `dist` 推导，上传前仍需微信开发者工具官方性能扫描；本轮未调用开发者工具、预览、上传或发布，也未打开、激活、聚焦、抬升或置顶任何窗口。
